卫星遥测参数智能分析助手

概述

本技能用于从 StarRocks 数据库中查询卫星遥测数据，根据用户自然语言问题自动提取参数、时间范围、阈值条件，执行相应分析并返回结果。覆盖六个核心场景：

1. 电压/电流/温度范围判断（含通电条件筛选、参数代码范围自动展开）
2. 卫星时间秒递增检查（PPS计数、卫星时间秒等是否每秒增加1）
3. LOG增长分析（提取LOG增长事件及对应的标记内容）
4. 飞轮转速跳变检测（基于稳定段基准值判断跳变）
5. 导航通信异常检测（通电区间内同时出现通信无效且异常计数增加）
6. 参数发现（列出指定卫星或时间范围的所有可用参数）

核心方法：用户提供自然语言问题，技能提取参数后调用对应 Python 脚本执行数据库查询，输出结构化 JSON，再转换为中文回复。

何时使用

必须使用本技能当用户询问以下任意模式的问题：

- 参数发现：“有哪些参数”、“参数列表”、“可用的测点”
- 电压/电流/温度范围判断：“蓄电池电压是否有低于28V？”、“负载电流是否控制在2.50-4.25A之间？”、“温度是否满足20±0.05？”、包含“WD-C001——WD-C015”等参数代码范围的问题
- 卫星时间秒递增：“卫星时间秒是否每秒增加1？”、“秒计数是否有跳变？”
- LOG增长：“LOG是否有增长？”、“增长的都是什么？”
- 飞轮跳变：“飞轮转速是否有跳变？”
- 导航通信异常：“是否有通信无效？”、“通信异常计数是否增加？”

不要使用本技能当用户：
- 没有提供卫星名称、时间范围等必要信息
- 要求修改、删除、写入遥测数据（本技能只读）
- 要求分析其他无关领域数据

## ⚠️ 强制预处理规则（在任何场景匹配前必须执行）

### 1. 卫星名称自动补全（必须执行，不可跳过）
- 如果用户输入的卫星名称以“高分”开头，且末尾没有“星”字，**必须**立即在末尾添加“星”字。
- 示例：“高分07B01” → “高分07B01星”；“高分07C01” → “高分07C01星”。
- 如果用户输入已经包含“星”，则保持原样。
- **严禁**将未经补全的卫星名称直接用于任何脚本调用。

### 2. 时间范围生成（全天查询，必须执行）
- 对于“全天”格式，**必须**生成 start_time = "YYYY-MM-DD 00:00:00"，end_time = "YYYY-MM-DD 00:00:00 +1 day"（即次日零点）。
- 示例：“20250718全天” → start="2025-07-18 00:00:00", end="2025-07-19 00:00:00"。
- 日期字符串解析：“20250718” → “2025-07-18”（自动添加连字符）。
- 脚本查询条件必须使用 createtime >= start AND createtime < end，禁止使用 BETWEEN。

### 3. 数值阈值提取（动态）
- 用户说“低于28V” → {"operator": "<", "value": 28}；阈值数字可变化（如“低于18V” → value=18）。

### 参数提取规则（严格模式）

#### 1. 卫星名称提取
- 按强制补全规则处理（见前文）。

#### 2. 主要参数（metrics）提取
- **必须**从用户消息中识别出需要判断数值范围的参数。
- 常见参数名称列表（供参考，但不限于）：
  - `蓄电池电压`、`负载电流`、`主镜A温度`、`飞轮1转速`
  - 参数代码如 `WD-C001`、`ZX-C120`
- 如果用户提到“电压”但未指定具体名称，默认使用 `蓄电池电压`。
- 如果用户提到“电流”且上下文提到“负载”，默认使用 `负载电流`。
- 如果用户明确给出参数代码（如 `WD-C001`），则使用代码格式，否则使用名称格式。
- **输出格式**：`{"type": "name", "value": "蓄电池电压"}` 或 `{"type": "code", "value": "WD-C001"}`。

#### 3. 数值条件（condition）提取
- 阈值数字必须从用户消息中直接提取，不得自行修改。
- 比较符识别：
  - `低于`、`小于`、`<` → `"<"`
  - `高于`、`大于`、`>` → `">"`
  - `之间`、`控制在...之间`、`~` → `"between"`
  - `±` → `"between"`（自动计算上下界）
- **示例**：
  - “低于28V” → `{"operator": "<", "value": 28}`
  - “2.50-4.25A” → `{"operator": "between", "min": 2.50, "max": 4.25}`
  - “20±0.05” → `{"operator": "between", "min": 19.95, "max": 20.05}`（AI 需计算 20-0.05 和 20+0.05）
- **容错**：如果提取到的数字明显异常（如负数、超出合理范围），可以提示用户确认；否则按提取值执行。

#### 4. 额外等值条件（extra_conditions）提取
- 识别用户消息中的“在...通电的情况下”、“在...断电的情况下”等短语。
- 提取出参数名称和期望的工程值（如“通电”、“断电”）。
- 参数名称通常是中文名称（如“成像处理箱通断”）。
- **输出格式**：`[{"name": "成像处理箱通断", "value": "通电"}, ...]`
- **容错**：如果找不到明确的参数名称，可尝试模糊匹配（如用户说“成像箱” → 匹配“成像处理箱通断”）。匹配规则见后文。

#### 5. 指标名称匹配与模糊匹配
- 优先精确匹配 `name` 或 `tmcode`。
- 若精确匹配失败，采用以下模糊规则：
  - 用户提供的字符串是某个已知参数名称的子串（例如“电压” → 匹配“蓄电池电压”）。
  - 用户提供的字符串与已知参数代码前缀相同（例如“WD-C00” → 匹配“WD-C001”）。
- 如果匹配到多个结果，选择最长的匹配项，或询问用户澄清。
- 如果无法匹配任何已知参数，回复：“未找到指标‘XXX’，当前可用参数有：[列出前10个]”。

#### 6. 提取失败时的处理
- 如果必要的参数（卫星名称、时间范围、主要参数）缺失，回复用户缺少什么信息，并给出示例。
- 如果条件阈值无法解析，回复：“请明确数值条件，例如‘低于28V’或‘2.50-4.25A’。”
- 如果通电条件中的参数名称不明确，回复：“请指明通电的参数名称，例如‘成像处理箱通断’。”

场景4：飞轮转速跳变

触发词：飞轮 + 转速 或 跳变

参数提取：卫星名称、时间范围、需要检查的飞轮列表（如“飞轮1、2、3、4”）

执行：调用 scripts/flywheel_jump.py，输入 JSON 包含 satellites, start_time, end_time, metrics（飞轮参数名称列表，字符串数组）。

基准值计算：对每个飞轮单独计算基准值。取时间正序的前5条记录，要求相邻记录工程值差的绝对值 ≤ 1，若满足则取这5条的平均值作为基准值；若不满足则滑动窗口继续，直到找到满足条件的5条记录。若全量记录均不满足，则无法计算基准值（脚本会跳过该飞轮并记录警告）。

跳变判定：当前工程值偏离基准值的比例 > 10% 即为跳变。

输出示例：
高分07B01星 飞轮4转速 在 2025-08-20 09:15:23.456 发生跳变：工程值 1999，基准值 500.0，偏差比例 299.8%。
其他飞轮未发现跳变。

场景5：导航通信异常

触发词：导航、通信无效、通信异常计数、主份导航通电

参数提取：卫星名称、时间范围

执行：调用 scripts/nav_comm_anomaly.py，输入 JSON 包含 satellites, start_time, end_time。

逻辑：
1. 提取“主份双频导航通断”、“导航通信状态”、“主份导航通信异常计数”三个参数的数据，按时间排序。
2. 识别通电区间（“主份双频导航通断”值为“通电”的连续时间段）。
3. 在每个通电区间内，检查是否存在“导航通信状态”为“通信无效”的记录，且“主份导航通信异常计数”在该区间内有增加（后值 > 前值）。
4. 若两者均满足，返回该区间内所有通信状态和异常计数的记录（补全参数代码）。

输出示例：
在通电区间（主份双频导航通断=通电）内，发现通信无效且异常计数增加的事件：

- 时间: 2025-08-01 14:38:01.894, 参数: 导航通信状态, 工程值: 通信无效
- 时间: 2025-08-01 14:38:01.894, 参数: 主份导航通信异常计数, 工程值: 0
...

参数提取规则（通用）

卫星名称
支持中文全称，如“高分07B01星”。若用户写“07B01星”，AI 应补全为完整名称（可通过通用前置步骤返回的卫星列表匹配）。

时间解析
“20250718全天” -> start="2025-07-18 00:00:00", end="2025-07-19 00:00:00"
“20250819230000-20250820050000” -> start="2025-08-19 23:00:00", end="2025-08-20 05:00:00"
“20250819000000-20250820050000” -> start="2025-08-19 00:00:00", end="2025-08-20 05:00:00"
若只给日期无时间，默认全天。

条件解析（场景1）
用户说法              生成的 condition
“低于28V”            {"operator": "<", "value": 28}
“2.50-4.25A”         {"operator": "between", "min": 2.50, "max": 4.25}
“20±0.05”            {"operator": "between", "min": 19.95, "max": 20.05}

参数代码范围展开（场景1）
- 支持模式：WD-C001——WD-C015、WD-C001-WD-C015、WD-C001~WD-C015
- 规则：提取前缀和数字部分，按数字递增生成所有中间代码。例如 WD-C001 到 WD-C015 生成 WD-C001, WD-C002, ..., WD-C015。
- 若无法解析（如非数字后缀），则保持原字符串并尝试精确匹配。

指标名称匹配（通用前置步骤中的关键任务）
AI 在获得参数列表后，按以下优先级匹配用户提到的指标：
1. 完全匹配 name 字段（如“蓄电池电压”）
2. 完全匹配 tmcode 字段（如“WD-C001”）
3. 模糊匹配（如用户说“电压”，匹配所有 name 中包含“电压”的参数，若多个则询问用户明确）
4. 范围展开（如“WD-C001——WD-C015” -> 生成代码列表，然后与 tmcode 匹配）

安全与令牌处理

本技能使用的数据库连接信息存储在 scripts/common_db.py 中，不包含在 SKILL.md 内。请确保该文件不被提交到公开仓库。

执行脚本时，数据库密码只用于本地连接，不会泄露到输出中。如果数据库连接失败，脚本会返回 status: error 并给出简要错误原因，不会暴露完整配置。

常见陷阱

1. 未执行通用前置步骤：直接调用场景脚本可能导致参数名不匹配。必须先获取参数列表。
2. 参数代码范围未展开：用户给的“WD-C001——WD-C015”必须展开为列表，否则数据库查不到。
3. 场景匹配错误：例如将“电压低于28V”误判为飞轮场景。必须按照优先级表严格匹配。
4. 时间解析错误：注意毫秒处理，脚本内部会忽略毫秒，但输入时间字符串需包含 YYYY-MM-DD HH:MM:SS 格式。
5. 忽略分页：指标查询接口可能只返回第一页，用户要求“全部”时需循环获取。
6. 不处理脚本错误：脚本返回 status: error 时应直接向用户报告 summary，而不是继续分析。
7. 输出中泄露数据库密码：回复内容不要包含 DB_CONFIG 的密码字段。
