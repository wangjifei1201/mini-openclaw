# 技术标格式检查

## 目标

辅助业务人员完成施工类技术标、暗标、明标的格式检查。

本技能的输出是 Markdown 检查报告和分层检查结论，用于人工确认和整改。不得直接修改 Word 文件，不得自动替换技术标内容，不做查重检查，不做最终投标合规法律判断。

## 最高原则

1. 用户提供的明确审查规则优先于一切。
2. 招标文件明确要求优先于内置通用规则。
3. 内置通用规则只能作为通用格式提示，不能直接当作项目硬性要求。
4. 大技术标默认分层、分步骤检查，不要一次性声称完成全部审查。
5. 无法自动判断时必须写明“无法自动判断”或“需人工确认”，不要假装确定。
6. 每条问题尽量给出文件名、段落序号、疑似页码、命中原文片段、依据和建议处理方式。

## 输入识别

收到用户请求后，先判断输入属于哪种模式。

### 模式 A：用户提供明确审查规则

用户可能上传或粘贴已经基于招标文件整理出的技术标审查规则。

这种模式优先级最高。直接按用户规则审查技术标。除非用户明确要求核对招标文件，否则不要用招标文件覆盖用户规则。

报告依据写为：

```markdown
依据：用户提供审查规则：第 X 条 / 原文片段
```

### 模式 B：用户提供招标文件

如果用户没有提供明确审查规则，但提供了招标文件，先从招标文件提取本项目技术标格式要求，再审查技术标。

重点检索：

- 暗标编制要求
- 技术标编制要求
- 投标文件格式
- 施工组织设计编制要求
- 否决投标条款
- 不允许出现 / 不得出现
- 字体、字号、颜色、加粗、倾斜、下划线
- 页边距、纸张大小、纸张方向
- 行距、段前段后、首行缩进、对齐方式
- 页眉、页脚、页码、目录、封面
- 图片、表格、附表
- 页数限制

报告依据写为：

```markdown
依据：招标文件第 X 页 / 第 X 段 / 原文片段
```

### 模式 C：只提供技术标

如果既没有明确审查规则，也没有招标文件，只能执行通用格式检查。

报告必须声明：

```markdown
未提供项目专属审查规则或招标文件，本报告仅基于通用格式检查规则，不判断项目专属硬性格式要求。
```

## 分层检查流程

分层检查是默认模式。对于大文件或多文件技术标，必须先规划，再分轮检查。

### 第 0 层：输入识别与检查计划

先输出检查计划，不直接进入全量检查。

检查计划应包括：

- 输入文件清单
- 技术标规模判断：单文件 / 多章节目录、段落数、页数或疑似页数
- 规则来源：用户规则 / 招标文件 / 通用规则
- 是否暗标 / 明标；无法判断时询问用户
- 建议分几轮检查
- 每轮检查范围和产出

建议轮次：

1. 检查基准确认
2. 硬性格式风险检查
3. 敏感词与项目一致性检查
4. 通用格式检索检查
5. 结构完整性与最终汇总

### 第 1 层：检查基准确认

目标是确认“本项目到底按什么规则检查”。

输出检查基准表，包括：

- 是否暗标
- 页数限制
- 纸张大小、方向、页边距
- 字体、字号、字形、颜色
- 行距、缩进、段前段后、对齐方式
- 页眉页脚页码要求
- 封面、目录、附表要求
- 图片、表格要求
- 不允许出现的内容
- 未明确规则项

如果规则来源不完整，标注“不明确”，并说明后续只能按通用规则提示。

### 第 2 层：硬性格式风险检查

优先检查可能影响暗标或被否决的硬性问题。

只在用户规则或招标文件有明确依据时，将问题列入“硬性格式风险”。

检查项：

- 暗标身份暴露
- 明确禁止的单位名称、Logo、CI、联系方式、人员身份信息
- 页眉、页脚、页码
- 文件属性异常
- 页数限制
- 明确禁止的目录、图片、表格、彩色内容
- 字体、字号、段落格式明显不符合明确规则
- 封面、大纲、附表缺失

输出：硬性格式风险报告。

### 第 3 层：敏感词与项目一致性检查

目标是发现模板残留和项目关键信息不一致。

检查项：

- 工程名称
- 工期 / 日历天
- 质量目标
- 安全文明目标
- 建设地点
- 省、市、区、县、乡、村、镇
- 历史项目类型残留
- 我局、八局、中建、工程局等
- EPC、施工总承包、工程总承包、管理总承包等需结合项目判断的词

输出：人工确认清单。

### 第 4 层：通用格式检索检查

执行内置关键词及格式检索表中的通用规则。

大文件或多文件目录应按文件/章节分批检查和输出，避免报告过长。

检查项：

- 标点
- 单位
- 空格、空行、制表符
- 重复词、错别字
- 大小写
- 特殊符号
- 异常标点组合

输出：通用格式问题报告。

### 第 5 层：结构完整性与最终汇总

检查结构完整性并汇总各轮结论。

检查项：

- 目录和正文标题是否一致
- 标题层级是否跳级
- 章节顺序
- 附表是否齐全
- 多文件技术标是否缺章
- 所有无法自动判断项汇总

输出：最终汇总报告。最终汇总只保留关键结论，详细命中保留在分轮报告中。

## 14 类检查框架

以下 14 类只作为检查维度，不作为固定取值。不同项目的具体标准由用户规则或招标文件确定。

1. 敏感内容检查
2. 纸张要求
3. 颜色要求
4. 页面要求
5. 正文要求
6. 标题要求
7. 表格要求
8. 图片要求
9. 页码要求
10. 封面要求
11. 目录要求
12. 页数要求
13. 默认检查
14. 不允许出现

每类检查按以下结构整理：

```markdown
检查维度：正文要求
本项目规则：
- 来源：用户规则 / 招标文件 / 未明确
- 规则原文：...
- 结构化要求：...
检查结果：符合 / 不符合 / 需人工确认 / 无法自动判断
```

未被用户规则或招标文件明确规定的项目，不得列为硬性格式风险。

## 内置通用检索规则

`技术标关键词及格式检索表.xlsx` 视为通用内置规则来源，用户不需要每次上传。

### 标点符号类

典型检查项：

- 英文逗号 `,` 建议改为中文逗号 `，`
- 英文分号 `;` 建议改为中文分号 `；`
- 英文冒号 `:` 建议改为中文冒号 `：`
- 英文括号 `(`、`)` 建议改为中文括号 `（`、`）`
- 重复标点：`。。`、`，，`、`、、`、`：：`、`；；`
- 异常标点组合：`。，`、`，。`、`。；`、`；。`、`。：`、`：。`、`，；`、`；，` 等
- 异常空行、空格、制表符
- 段落末尾疑似无标点

### 单位类

典型检查项：

- `Mpa`、`mpa` → `MPa`
- `KN` → `kN`
- `KG`、`Kg` → `kg`
- `KW` → `kW`，但附表一中 `KW` 不得机械替换，需人工确认
- `KV` → `kV`
- `HZ` → `Hz`
- `PH` → `pH`
- `/S` → `/s`
- `m3` → `m³`
- `m2` → `㎡`
- `mm2`、`cm2` 中的 2 应考虑上标
- 数字后缺少厚度单位，如 `8厚` 需人工确认是否为 `8mm厚` 或 `8cm厚`
- 范围连接符如 `1-3` 需确认是否应为 `1～3`

### 关键词类

典型检查项：

- 省、市、区、县、乡、村、镇等地名词
- 陕西、甘肃、青海、新疆、浙江、山西、内蒙、宁夏、四川等历史区域词
- 上海、杭州、西安、兰州、乌鲁木齐、呼和浩特等城市名
- 我局、八局、中建、工程局
- EPC、工程总承包、施工总承包、管理总承包、PC
- 住宅、医院、学校、厂房、机场、航站楼、车间等工程类型
- 奖、杯、局标准化管理手册、cscec
- 下图、下表
- 资审文件、招标文件、投标文件

这些词多数进入“人工确认项”，除非项目规则明确禁止。

### 岗位及部门名称类

典型检查项：

- 项目负责人、项目经理、设计负责人、生产经理、项目总工、质量总监、安全总监、机电经理、商务经理
- 专业工程师、施工管理人员、绿色施工员、劳务管理员、安全员、质量员、材料员、试验员、测量员
- 质量管理部 / 质量部
- 安全管理部 / 安全部
- 工程管理部 / 工程部
- 机电管理部 / 安装部
- 物资设备部 / 物资部
- 商务管理部 / 商务部
- 技术管理部 / 技术部
- 设计部 / 设计管理部，需确认是否为 EPC 项目

这些词主要用于岗位和组织架构一致性确认。

### 目标类

典型检查项：

- 质量目标、质量管理目标、质量要求
- 安全目标、安全文明目标、安全管理目标、安全生产目标、安全要求
- 文明施工目标、文明施工管理目标、文明施工要求
- 工期目标、总进度目标、工期管理目标、日历天

这些词需要与用户规则或招标文件中的基准信息一致。

### 格式类

典型检查项：

- 全文文字颜色是否为自动或规则要求颜色
- 字体主体颜色是否无填充
- 导航窗格中标题是否跳级
- 正文中是否混入标题编号
- 标题中是否含不允许的冒号、句号等

## 报告分类

每条问题必须归入以下之一：

1. 硬性格式风险
2. 人工确认项
3. 通用格式问题
4. 优化建议
5. 无法自动判断项

分类规则：

- 有明确项目规则依据且不符合：硬性格式风险。
- 需要结合项目事实判断：人工确认项。
- 明显通用格式错误：通用格式问题。
- 不影响硬性要求但可提升一致性：优化建议。
- 当前工具或材料无法可靠判断：无法自动判断项。

## 大文件处理要求

当技术标文件很大、章节很多或命中项很多时：

1. 先输出检查计划。
2. 每轮只检查一类问题。
3. 分文件或分章节处理。
4. 每轮报告只保留本轮结果。
5. 最终汇总报告只保留关键结论。
6. 每轮结束说明下一轮建议。

可建议用户将分轮报告保存为：

- `00-check-plan.md`
- `01-check-baseline.md`
- `02-hard-format-risks.md`
- `03-sensitive-consistency.md`
- `04-common-format-issues.md`
- `05-final-summary.md`

## 无法自动判断时的写法

使用以下格式：

```markdown
状态：无法自动判断
原因：当前材料或工具无法可靠读取该项，例如复杂 Word 样式继承、WPS 与 Word 渲染差异、图片是否真实黑白、页码与分页位置、文本框或页眉页脚隐藏内容等。
人工复核方法：请在 Word/WPS 中通过对应菜单人工检查。
```

## 严禁事项

- 不得直接修改技术标文件。
- 不得自动批量替换 Word 内容。
- 不得做查重检查。
- 不得把通用规则说成项目硬性要求。
- 不得在没有依据时使用“废标”作为确定结论。
- 不得一次性声称已完整检查超大技术标的所有问题。
- 不得隐藏无法自动判断的限制。

## 结束语要求

每轮检查结束时，用简短文字说明：

- 本轮完成了什么。
- 有哪些关键发现。
- 下一轮建议检查什么。

不要输出冗长总结。
